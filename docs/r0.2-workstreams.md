# R0.2 workstreams and ownership

**Updated:** 2026-09-20  
**Goal:** complete the first reproducible training release without hiding unfinished acceptance work

Ownership is explicit so work can proceed in parallel. The named owner is responsible for producing
the evidence or decision; Codex remains responsible for integration, review and keeping the release
requirements honest.

## User-owned

| Work | Deliverable | Status |
|---|---|---|
| Enrol the second home GPU machine | The second machine appears online in the `Home` group with actual capability and GPU health evidence | Ready when the machine is accessible |
| Select the first useful model and dataset | A short description of the real training goal and where its authorised data comes from | Pending; the bundled smoke workload does not block this choice |
| Witness the physical disconnect exercise | Disconnect the selected worker when prompted, then reconnect it after the lease/result checks | Pending an exact runbook from Codex |

The user SHALL NOT need to edit database records, copy cloud credentials to a worker or manually
construct internal API requests for these tasks.

## Current release boundary

The production system can queue and execute an immutable GPU container, safely cancel queued and
active work, and recover expired leases with a bounded retry. R0.2 is not complete until a real
training run records exact inputs and durable outputs and a network-loss exercise demonstrates that
the lease and replay rules do not duplicate execution.
